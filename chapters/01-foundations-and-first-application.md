## What I am learning here

Spring Boot helps assemble a Spring application with sensible defaults, managed dependencies, and an embedded server. It reduces setup work, but the application still has clear Java classes and responsibilities. Spring Framework provides the core container and web features; Boot configures common pieces based on dependencies and settings.

For a new project, Spring Initializr can create the Maven or Gradle structure. I select Java, Spring Boot 4.1.1, a supported Java version, and the dependencies needed for the first feature. The official requirements currently list Java 17 as the minimum. These notes use Java 21 in examples.

## Minimal Maven dependencies

A Spring MVC application on Boot 4 uses the webmvc starter. Its matching test starter provides MVC test support.

~~~xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.1</version>
    <relativePath/>
</parent>

<properties>
    <java.version>21</java.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
~~~

The Spring Boot parent manages compatible dependency versions. I normally do not add versions to dependencies managed by that parent. Boot 4 has modular starters, so I choose the one that matches the application instead of copying an older starter name.

## Create the application entry point

~~~java
package com.example.notes;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class NotesApplication {
    public static void main(String[] args) {
        SpringApplication.run(NotesApplication.class, args);
    }
}
~~~

@SpringBootApplication combines configuration, component scanning, and auto-configuration behavior. SpringApplication.run creates the application context and starts the embedded server when a web starter is present.

## Return a first response

~~~java
package com.example.notes;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
class GreetingController {
    @GetMapping("/api/greeting")
    GreetingResponse greeting() {
        return new GreetingResponse("Hello, Spring Boot");
    }
}

record GreetingResponse(String message) {}
~~~

Run the application with the Maven wrapper generated by Spring Initializr:

~~~sh
./mvnw spring-boot:run
~~~

A request to /api/greeting returns JSON. Records are a concise way to model simple immutable response data in modern Java.
